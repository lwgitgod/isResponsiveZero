## 4. CONTEXT YOU NEED

**The headline finding.** The Priority 1 complaint ("questionnaire doesn't work") was **not** missing
features. Almost everything was built. It was disconnected at two layers: three finished views had no
button that opened them, and **no Complaint Checker migration had ever run against any tenant
database**. Both are now fixed.

**Why the migrations never ran.** Every tenant DB was stamped
`cc504_merge_soft_delete_dev_head` — a revision that exists **only** on
`ComplaintChecker-stage1--ABANDONED`. The databases were *born from that branch's `dump.sql`*, not
migrated into that state. Alembic could not locate the revision and refused to run.
Note: `git log -S` **skips merge commits by default** and will tell you that revision does not exist.
Use `git cat-file -e <branch>:<path>`.

**Abandoned tables were never deployed** — proven from git, no database contacted. The creating commit
`2dc8fc1` is on `ComplaintChecker-stage1` / `--ABANDONED` only; `git merge-base --is-ancestor` is false
against `dev`, `origin/dev`, `main`, `origin/main`; and `git grep -l "complaint_check" origin/dev --
db/migrations/` returns nothing at all.

**Two paths in `SPEC/CC/` are easy to miss.** `proposedtables.sql` exists and is a real design document
— glob for `*.sql`, not just `*.md`. And **never read `SPEC/CC/ARCHIVE/`** (Prime Directive #1).

**The design that shipped is not `proposedtables.sql`.** That file put the token in the tenant DB.
What shipped puts it in `LegaAuth` as `complaint_check_grant`, because an unauthenticated client
request has no way to know which tenant DB to open. Three tables, not two.

**The runner is the only test.** Prime Directive #4 permits no other. So every "PASS n/n" is only as
good as the harness. CC-Ticket15 established the rule, now in the runner's module docstring:
**a step must establish the precondition it asserts, and must pass twice in a row on the same
database.** A false green already happened twice this run.

**Verify agent claims by running the step yourself.** This paid off twice — CC-Ticket4 reported
`freeze 20/20`, true only as a first run; the real state was 17/20 on repeat.

**Environment gotchas, all confirmed:**
- `conda run -n lw-core-api-dev-env` crashes in Git Bash here. Use
  `/c/Users/rossb/.conda/envs/lw-core-api-dev-env/python.exe` directly.
- `PYTHONIOENCODING=utf-8` or `db/database_specific.py:275` raises `UnicodeEncodeError`.
- **Git Bash rewrites absolute paths** — `docker exec … psql -f /tmp/x.sql` becomes a Windows path and
  fails. Use `MSYS_NO_PATHCONV=1` and `//tmp/x.sql`.
- `legawrite-app` mounts `.:/app`, so uncommitted source changes are **live** in the running app.
- The running backend image predates several commits; `localhost:47312/openapi.json` will not list the
  newest routes. Work from controller source. **Do not tell the owner to rebuild** (Prime Directive #5).
- `Corporate_design/lwDesign.md` **does not exist** — the file is `lwDesign2.md`, despite Prime
  Directive #6 citing the missing name.
